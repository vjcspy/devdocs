## User Requirements

> * Meta repo chứa nhiều CLI tools theo domain (ví dụ `nab/`, `common/`, `tinybots/`).
> * Mỗi tool có thể viết bằng Node.js hoặc Python (tuỳ "nhanh gọn" hay "cần Python").
> * **Unified CLI**: Tất cả tools đều accessible qua một command duy nhất `dt <subcommand>`.
> * Folder structure theo **domain/project**, **không chia theo ngôn ngữ** (tất cả CLI đều nằm trong `cli/`).
> * Package naming theo **feature** (không prefix `devtools-`).
> * Cần "uv config ở root tương tự pnpm" để quản lý mono repo Python.
> * Máy công ty bị chặn `uv` → vẫn phải chạy được bằng `pip`.
> * Root có **`requirements.txt`** dùng cho **toàn bộ** Python tools, do `uv` generate ra (pinned + transitive).

---

## 🎯 Objective

> Thiết kế và chuẩn hoá một unified CLI monorepo có thể:
>
> * **Single entry point**: `dt <subcommand>` cho tất cả tools (Python + Node)
> * Python plugins: auto-discover via entry points (`dt.plugins`)
> * Node plugins: load via registry + subprocess wrapper
> * Quản lý Python bằng uv workspace (lock 1 lần cho cả repo)
> * Quản lý Node bằng pnpm workspace
> * Luôn có "fallback path" chạy được trên máy không có uv bằng `pip install -r requirements.txt`

### 🖥️ Supported Platforms

> **macOS, Linux** only. Windows is out of scope for this implementation.

### ⚠️ Key Considerations

> 1. **Single Python environment / single lock**: uv workspace dùng **một lockfile chung** cho toàn workspace members → đảm bảo versions nhất quán. ([Astral Docs][1])
> 2. **Conflict policy**: Nếu 2 tool cần 2 versions incompatible của cùng 1 dependency, cả uv sync và pip fallback đều sẽ fail (đây là "constraint" của mô hình 1 env).
> 3. Root `requirements.txt` là "portable lock artifact" cho môi trường không có uv, được generate từ lock (uv export). ([Astral Docs][2])
> 4. **Dual plugin system**: Python dùng entry points (native), Node dùng registry file + subprocess.
> 5. Internal deps (workspace members) phải khai báo `[tool.uv.sources] ... { workspace = true }` **trong pyproject.toml của member sử dụng dependency đó** (không phải root). ([Astral Docs][4])
> 6. **Unified CLI**: Chỉ cần link 1 command `dt` thay vì nhiều commands riêng lẻ.
> 7. **Không chia folder theo ngôn ngữ**: Tất cả CLI tools (Python + Node) đều nằm trong `<domain>/cli/`, phân biệt bằng file marker (`pyproject.toml` vs `package.json`).

|------|-----------|-----------|----------|

### Phase 3: Detailed Implementation

#### 3.1 Root CLI (`common/cli/dt-core`) ✅

**`common/cli/dt-core/pyproject.toml`**:

```toml
[project]
name = "dt-core"
version = "0.1.0"
description = "Unified CLI for development tools"
requires-python = ">=3.12"
dependencies = ["typer>=0.12", "rich>=13.0", "pyyaml>=6.0"]

[project.scripts]
dt = "dt_core.main:app"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/dt_core"]
```

**`common/cli/dt-core/src/dt_core/main.py`**:

```python
import typer
from dt_core.python_loader import load_python_plugins
from dt_core.node_loader import load_node_plugins

app = typer.Typer(
    name="dt",
    help="Unified CLI for development tools",
    no_args_is_help=True,
)

@app.command()
def version():
    """Show dt version."""
    from dt_core import __version__
    typer.echo(f"dt version {__version__}")

# Load plugins
load_python_plugins(app)
load_node_plugins(app)

if __name__ == "__main__":
    app()
```

#### 3.2 Plugin Registry (`dt-plugins.yaml`)

Auto-generated by `scripts/generate-registry.py`:

```yaml
# Auto-generated by scripts/generate-registry.py
# Do not edit manually. Run: python scripts/generate-registry.py

plugins:
  # Python plugins (discovered via entry points, listed for documentation)
  metan:
    type: python
    entry: metan.cli:app
    path: nab/cli/metan

  # Node plugins (loaded via this registry)
  foo:
    type: node
    bin: nab/cli/foo/dist/cli.js
    path: nab/cli/foo
    description: "Foo build tools"
```

#### 3.3 Python Plugin Example (`nab/cli/metan`) ✅

**`nab/cli/metan/pyproject.toml`**:

```toml
[project]
name = "metan"
version = "0.1.0"
description = "Metan domain tools"
requires-python = ">=3.12"
dependencies = ["typer>=0.12", "dt-core"]

[project.entry-points."dt.plugins"]
metan = "metan.cli:app"

[tool.uv.sources]
dt-core = { workspace = true }

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/metan"]
```

**`nab/cli/metan/src/metan/cli.py`**:

```python
import typer

app = typer.Typer(help="Metan domain tools")

@app.command()
def sync(
    source: str = typer.Argument(..., help="Data source"),
    dry_run: bool = typer.Option(False, "--dry-run", "-n"),
):
    """Sync metan data from source."""
    typer.echo(f"Syncing from {source}..." + (" (dry run)" if dry_run else ""))

@app.command()
def report(format: str = typer.Option("json", "--format", "-f")):
    """Generate metan report."""
    typer.echo(f"Generating {format} report...")

@app.command()
def status():
    """Show metan system status."""
    typer.echo("Metan Status")
    typer.echo("=" * 40)
    typer.echo("Connection: OK")
```

#### 3.4 Node Plugin Example (`nab/cli/foo`) ✅

> **Note**: Node plugin cũng nằm trong `cli/` folder, không phải `node/` folder.

**`nab/cli/foo/dt-plugin.yaml`** (marker for registry scanner):

```yaml
name: foo
description: Foo build and deployment tools
bin: dist/cli.js
```

**`nab/cli/foo/package.json`**:

```json
{
  "name": "@nab/foo",
  "version": "0.1.0",
  "description": "Foo build and deployment tools",
  "type": "module",
  "bin": {
    "nab-foo": "./dist/cli.js"
  },
  "scripts": {
    "build": "tsc",
    "dev": "tsc --watch"
  },
  "dependencies": {
    "commander": "^12.0.0"
  },
  "devDependencies": {
    "@types/node": "^20.0.0",
    "typescript": "^5.0.0"
  }
}
```

**`nab/cli/foo/src/cli.ts`**:

```typescript
#!/usr/bin/env node
import { Command } from 'commander';

const program = new Command();

program
  .name('foo')
  .description('Foo build and deployment tools')
  .version('0.1.0');

program
  .command('build')
  .description('Build the project')
  .option('-w, --watch', 'Watch mode')
  .action((options) => {
    console.log('Building...', options.watch ? '(watch mode)' : '');
  });

program
  .command('deploy')
  .argument('<env>', 'Target environment')
  .action((env) => {
    console.log(`Deploying to ${env}...`);
  });

program.parse();
```

### Phase 4: Developer Workflow & CI

#### 4.1 Daily Developer Workflow

| Scenario | Command |
|----------|---------|
| Thêm Python plugin mới | Tạo `<domain>/cli/<name>/` với `pyproject.toml` + entry point |
| Thêm Node plugin mới | Tạo `<domain>/cli/<name>/` với `package.json` + `dt-plugin.yaml` |
| Thêm external dependency | `uv add <pkg>` trong member folder → `uv lock` |
| Sau khi thêm plugin | `python scripts/generate-registry.py` |
| Thay đổi code | Không cần reinstall (đã editable) |
| Pull code từ remote | `uv sync` hoặc `pip install -r requirements.txt` |

#### 4.2 Usage Examples

```bash
# Unified CLI
dt --help
# Commands:
#   version     Show dt version
#   metan       Metan domain tools (Python)
#   foo         Foo build tools (Node)

# Python plugins
dt metan sync source-a --dry-run
dt metan status

# Node plugins (transparent subprocess)
dt foo build --watch
dt foo deploy staging

# Node plugins still accessible directly
nab-foo build --watch
```

#### 4.3 Setup Commands

```bash
# First time setup
cd devtools
chmod +x scripts/*.sh scripts/*.py
./scripts/install-all.sh

# Or manual steps:
uv sync                              # Install Python packages
pnpm install && pnpm -r build        # Install & build Node packages
python scripts/generate-registry.py  # Generate plugin registry
```

#### 4.4 CI Workflow

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  test-uv:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v4
      - run: uv sync
      - run: uv run python scripts/generate-registry.py
      - run: uv run dt --help
      - run: uv run dt metan --help

  test-pip-fallback:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Install via pip fallback
        run: |
          python -m venv .venv
          source .venv/bin/activate
          pip install -r requirements.txt
          for dir in common/cli/* nab/cli/*; do
            [ -d "$dir" ] && [ -f "$dir/pyproject.toml" ] && pip install -e "$dir" --no-deps
          done
          python scripts/generate-registry.py
      - name: Verify CLI
        run: |
          source .venv/bin/activate
          dt --help

  test-node:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "pnpm"
      - run: pnpm install
      - run: pnpm -r build
```
