# 📋 [TICKET-ID: 2026-01-20] - Meta Monorepo (uv + pnpm) for Mixed Node & Python CLI Tools with Root `requirements.txt` Fallback

## References

* uv workspaces concept & config: ([Astral Docs][1])
* uv export → requirements.txt: ([Astral Docs][2])

---

## User Requirements

> * Meta repo chứa nhiều CLI tools theo domain (ví dụ `projects/projectA`, `projects/projectB`).
> * Mỗi tool có thể viết bằng Node.js hoặc Python (tuỳ “nhanh gọn” hay “cần Python”).
> * Tất cả đều là CLI, cần link ra global command.
> * Không muốn chia folder theo ngôn ngữ (không có `python/` `node/`).
> * Cần “uv config ở root tương tự pnpm” để quản lý mono repo Python.
> * Máy công ty bị chặn `uv` → vẫn phải chạy được bằng `pip`.
> * Root có **`requirements.txt`** dùng cho **toàn bộ** Python tools, do `uv` generate ra (pinned + transitive).
> * Script để install all cho cả Node và Python.
> * Ví dụ một package Python:
>
>   * `[project]` có `dependencies` gồm external (`celery[librabbitmq]>=5.3.6`) + internal workspace members (`metan-core`, `metan-stock`)
>   * `[project.scripts]` expose command `metan = "metan.cli.main:app"`

## 🎯 Objective

> Thiết kế và chuẩn hoá một meta monorepo có thể:
>
> * Quản lý Node CLIs bằng pnpm workspace
> * Quản lý Python CLIs bằng uv workspace (lock 1 lần cho cả repo)
> * Luôn có “fallback path” chạy được trên máy không có uv bằng `pip install -r requirements.txt`
> * Sau khi install xong, **tất cả CLI commands đều usable** (qua script link)

### 🖥️ Supported Platforms

> **macOS, Linux** only. Windows is out of scope for this implementation.

### ⚠️ Key Considerations

> 1. **Single Python environment / single lock**: uv workspace dùng **một lockfile chung** cho toàn workspace members → đảm bảo versions nhất quán. ([Astral Docs][1])
> 2. **Conflict policy**: Nếu 2 tool cần 2 versions incompatible của cùng 1 dependency, cả uv sync và pip fallback đều sẽ fail (đây là “constraint” của mô hình 1 env).
> 3. Root `requirements.txt` là “portable lock artifact” cho môi trường không có uv, được generate từ lock (uv export). ([Astral Docs][2])
> 4. uv workspace config ở root sẽ “override/ignore” config ở members; config shared tại root. ([Astral Docs][3])
> 5. Internal deps (workspace members) phải khai báo `[tool.uv.sources] ... { workspace = true }` **trong pyproject.toml của member sử dụng dependency đó** (không phải root). ([Astral Docs][4])
> 6. Global commands: Node có thể link global bằng pnpm; Python commands cần được “expose” thông qua environment bin (venv) hoặc shim/symlink → viết script link.

### Phase 3: Detailed Implementation Steps

#### 3.1 Root uv workspace config (pyproject.toml)

**Goal**: root “virtual workspace package” để uv có nơi neo config + define members.

**Root `pyproject.toml` tối thiểu (pattern khuyến nghị)**

* Có `[tool.uv.workspace] members = [...]` ([GitHub][5])
* Có thể giữ `[project] dependencies = []` (root không cần là tool chạy).

Ví dụ skeleton:

```toml
[project]
name = "meta-workspace"
version = "0.1.0"
requires-python = ">=3.12.10"
dependencies = []

[tool.uv.workspace]
members = [
  "projects/projectA/metan-cli",
  "projects/projectA/metan-core",
  "projects/projectA/metan-stock",
  # ... add more members
]
```

**Internal workspace dependency mapping**
Để member `metan-cli` có thể phụ thuộc `metan-core` / `metan-stock` theo kiểu workspace member, khai báo **trong pyproject.toml của member đó** (không phải root):

```toml
# projects/projectA/metan-cli/pyproject.toml
[project]
name = "metan-cli"
dependencies = ["metan-core", "metan-stock", "celery[librabbitmq]>=5.3.6"]

[tool.uv.sources]
metan-core = { workspace = true }
metan-stock = { workspace = true }
```

> ⚠️ **Lưu ý**: `[tool.uv.sources]` đặt ở **member's pyproject.toml**, không phải root. Root chỉ cần `[tool.uv.workspace]` để define members. ([Astral Docs][4])

> **Context requirement quan trọng**: với uv workspace, “members phải explicitly stated” (không auto-discover). ([Astral Docs][4])
> → nên chọn 1 trong 2:
>
> * **Explicit list** (chắc chắn, rõ ràng)
> * Hoặc maintain list bằng script generator (không bắt buộc ngay trong ticket này)

#### 3.2 Root requirements.txt as portable lock artifact

**Contract**:

* `requirements.txt` ở root là file **pinned + transitive** export từ `uv.lock`, để **pip-only** environment cài y chang versions.
* Generate bằng: `uv export --format requirements.txt --output-file requirements.txt` ([Astral Docs][2])
* Quy ước workflow:

  * Dev machine có uv: update deps → `uv lock` → `scripts/export-requirements.sh` → commit cả `uv.lock` + `requirements.txt`

#### 3.3 Node monorepo config (pnpm)

* `pnpm-workspace.yaml`:

  * include toàn bộ node packages dưới `projects/**` (pnpm tự nhận folder có `package.json`)

Ví dụ:

```yaml
packages:
  - "projects/**"
```

#### 3.4 Install-all orchestration (uv-first, pip-fallback)

**scripts/install-all.sh** (logic spec, không cần code trong ticket plan):

1. `doctor` check:

   * Node: `node`, `pnpm`
   * Python: `python`, `pip`
   * optional: `uv`
2. Node install:

   * `pnpm -r install`
   * `pnpm -r build` (hoặc build per package)
3. Python install:

   * Nếu có `uv`:

     * `uv sync` (install workspace deps + editable members tự động)
     * đảm bảo `requirements.txt` cập nhật (fail nếu dirty)
   * Nếu không có `uv` **(pip-fallback flow)**:

     * tạo venv `.venv`
     * `pip install -r requirements.txt` (chỉ install external deps)
     * **Editable install workspace members** (theo dependency order):
       ```bash
       pip install -e projects/projectA/metan-core --no-deps
       pip install -e projects/projectA/metan-stock --no-deps
       pip install -e projects/projectA/metan-cli --no-deps
       ```
     * ⚠️ `requirements.txt` không chứa workspace members → phải editable install riêng để có CLI entrypoints
4. Cuối cùng gọi `scripts/link-commands.sh`

> **Context requirement**: Mục tiêu là “install all for whole repo” → không cài lẻ. Script là “one-shot entrypoint”.

#### 3.5 Link commands (Node + Python)

**Node**:

* loop mọi package có `package.json` và field `bin` → `pnpm link --global` (hoặc cơ chế tương đương theo chuẩn pnpm version của bạn)

**Python**:

* Sau khi install vào `.venv`, command nằm ở `.venv/bin/<script-name>`
* `link-commands.sh` tạo shim/symlink vào `~/.local/bin` (Mac/Linux) để global usable:

  * `ln -sf <repo>/.venv/bin/metan ~/.local/bin/metan`
* Script phải detect `[project.scripts]` để biết cần link command nào (hoặc đơn giản link toàn bộ executable do venv tạo ra, nhưng nên whitelist để tránh rác)

#### 3.6 Package-level Python config (example alignment)

Package `projects/projectA/metan-cli/pyproject.toml` (đúng với requirement user):

* `[project]`:

  * `dependencies` gồm external + internal members (`metan-core`, `metan-stock`)
* `[project.scripts]`:

  * expose `metan = "metan.cli.main:app"`

**Lưu ý** (để uv workspace hiểu internal deps đúng):

* Trong package-level `pyproject.toml`, dependencies list chứa `metan-core`, `metan-stock`
* Cùng file đó phải có `[tool.uv.sources]` với `{ workspace = true }` như đã nêu ở 3.1 ([Astral Docs][4])

### Phase 4: Developer Workflow & CI

#### 4.1 Daily Developer Workflow

**Sau khi setup xong (`scripts/install-all.sh`):**

| Scenario | Command |
|----------|---------|
| Thêm external dependency | `uv add <pkg>` trong member folder → `uv lock` → `scripts/export-requirements.sh` |
| Thêm workspace member mới | Tạo folder + pyproject.toml → thêm vào root `members` → `uv sync` |
| Thay đổi code trong member | Không cần reinstall (đã editable install) |
| Pull code từ remote | `uv sync` hoặc `pip install -r requirements.txt` nếu lock thay đổi |

#### 4.2 CI Workflow Skeleton

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  test-uv:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v4
      - run: uv sync
      - run: uv run metan --help

  test-pip-fallback:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Install via pip fallback
        run: |
          python -m venv .venv
          source .venv/bin/activate
          pip install -r requirements.txt
          pip install -e projects/projectA/metan-core --no-deps
          pip install -e projects/projectA/metan-stock --no-deps
          pip install -e projects/projectA/metan-cli --no-deps
      - name: Verify CLI
        run: |
          source .venv/bin/activate
          metan --help

  test-node:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "pnpm"
      - run: pnpm -r install
      - run: pnpm -r build
```
